### 3. Exact semantic scope

The slice covers only the normal `ProtocolRelease` semantic type.

A final identity is:

```text
ghostbridge/e<epoch>.r<revision>
```

A non-final identity is:

```text
ghostbridge/e<epoch>.r<revision>-<stage>.<iteration>
```

`epoch`, `revision`, and `iteration` are canonical unsigned ASCII decimal components:

- Range `0..2147483647`, inclusive.

- One through ten digits.

- Exact `0` is permitted.

- Every other value begins with `[1-9]`.

- No leading zero, sign, decimal point, exponent, whitespace, wrapping, clamping, coercion, rounding, or lossy numeric path.

- Every ten-digit value greater than `2147483647` rejects.

The non-final stage is exactly one of:

```text
experimental
draft
alpha
beta
rc
```

The complete identity is lowercase ASCII, exactly spelled, and case-sensitive. No trimming, Unicode normalization, case folding, punctuation repair, alias substitution, or malformed-input canonicalization is permitted.

Equality is exact string equality between two independently validated normal identities.

Ordering is a total preference/chronology order over valid normal identities:

1. Integer epoch.

2. Integer revision.

3. Stage rank:

   ```text
   experimental < draft < alpha < beta < rc < final
   ```

4. Integer iteration when both identities have the same non-final stage.

Stage rank precedes iteration. Final follows every `rc` iteration with the same epoch and revision.

Invalid identities are not orderable and MUST be rejected before equality or comparison produces a result.

Ordering MUST NOT imply compatibility, implementation support, release support, conformance, security eligibility, safety, lifecycle state, or authority.

`ProtocolRelease` remains a distinct semantic type from every other version or identity class enumerated by REQ-VERS-0003.

`ghostbridge/0.1-draft` remains an immutable legacy identity outside the normal grammar. The new schema and semantic owner MUST reject it. This slice neither implements nor redesigns legacy-reader behavior.

### 5. Structural-versus-semantic ownership

`ProtocolRelease` is one JSON string. Stage is not an embedded JSON member.

The primitive schema MUST require:

- JSON type `string`.

- `maxLength: 59`.

- An exact full-string Draft 2020-12 pattern, or demonstrably equivalent structural form, matching only the accepted final and non-final grammar.

The required full-string language is equivalent to:

```regex
^ghostbridge/e(?:0|[1-9][0-9]{0,9})\.r(?:0|[1-9][0-9]{0,9})(?:-(?:experimental|draft|alpha|beta|rc)\.(?:0|[1-9][0-9]{0,9}))?(?![\s\S])
```

The implementation must verify genuine full-string behavior, including rejection of trailing line terminators and other partial-match cases.

The non-final pattern alternative permits exactly `experimental`, `draft`, `alpha`, `beta`, or `rc`. It permits no sixth token, case variant, alias, prefix match, or suffix match.

The longest valid normal identity is:

```text
ghostbridge/e2147483647.r2147483647-experimental.2147483647
```

Its length is exactly 59 ASCII characters and 59 UTF-8 octets. This is a derivation from the accepted grammar, not a new wire-size policy.

The semantic owner MUST reject candidate strings longer than 59 characters before applying its regex or parsing components. Wrong JSON types reject before the length check.

| Concern | Structural ownership | Semantic ownership |
|---|---|---|
| JSON carrier | String type | Entry-point type guard |
| Length | Maximum 59 | Pre-regex length rejection |
| Prefix, separators, final/non-final form | Full-string schema grammar | No repair or fallback |
| Decimal lexical form | `0` or one-to-ten canonical digits | Exact component extraction |
| Stage spelling | Exact pattern alternatives | Fixed explicit stage-rank table |
| `2147483647` upper bound | Not required structurally | Mandatory exact range enforcement |
| Ten-digit over-max value | May pass the lexical schema | Must fail semantic validation |
| Equality | Not schema-expressible | Exact validated-string equality |
| Ordering | Not schema-expressible | Exact component comparison |
| Type separation and nonimplications | Not proven by a scalar schema | Semantic/API/review boundary |

The semantic-constraint inventory MUST own the numeric upper bound explicitly. Schema-only enforcement MUST NOT be claimed.

Structural plus semantic validation MUST reject every identity invalid under REQ-VERS-0001.

### 7. Comparator invariants

Comparison of every pair of valid normal releases MUST return exactly one of `LESS`, `EQUAL`, or `GREATER`.

Required evidence includes:

- Equality consistency: `EQUAL` if and only if exact validated-string equality is true.

- Antisymmetry: operand reversal reverses `LESS` and `GREATER`; `EQUAL` remains `EQUAL`.

- Transitivity.

- Totality.

- The complete stage chain.

- Epoch precedence over revision, stage, and iteration.

- Revision precedence over stage and iteration.

- Stage precedence over iteration.

- Iteration precedence only within the same non-final stage.

- Final after every `rc` iteration at equal epoch and revision.

- Permutation and input-order independence.

- Locale independence.

- Deterministic repeated execution.

- No reliance on sort stability.

Comparator-property tests may mechanically enumerate relations over a fixed reviewed set, but canonical expected ordering must remain independently specified.
