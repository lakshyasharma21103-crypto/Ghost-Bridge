# Production protocol benchmark

## Method

This benchmark uses only the observations in `phase-15d0-reference-register.md`. Every reference practice below is a **Verified external reference observation supplied by independent review.** Codex did not directly inspect the external repositories.

The benchmark compares reusable protocol-engineering practices, not MCP-specific semantics. No row proposes an MCP wrapper, MCP runtime dependency, MCP authority model, or direct Agent-to-Agent authority. Ghost Bridge's trusted installation, Install Grants, Connection authority, organization/workspace scope, governed Invocations, exact-action Approvals, durable Tasks, signed Receipts, Trust verification, and anti-rollback requirements remain controlling.

Evidence path shorthand follows the gap audit: a bare `*.md` specification name resolves under `protocol/specification/0.1-draft/`, a bare `*.schema.json` under `protocol/schemas/0.1-draft/`, and a leading `:<lines>` continues the immediately preceding full path.

Severity is the risk to independent production implementation: `CRITICAL`, `HIGH`, `MEDIUM`, `LOW`, or `INFORMATIONAL`.

## Benchmark conclusion

Ghost Bridge already separates major package roles and has meaningful security-oriented implementation work. It does not yet satisfy the reusable production-protocol practices above because normative behavior, complete wire contracts, state machines, compatibility rules, test vectors, and implementation-neutral conformance are incomplete.

The benchmark does not find a reason to convert Ghost Bridge into MCP. The required correction is to make Ghost Bridge's own protocol explicit and independently implementable.
